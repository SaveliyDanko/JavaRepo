# Apache Kafka в Spring

Краткая теоретическая сводка. Код — в `src/main/java/com/savadanko/javarepo/kafka/`.

## Что это и зачем

**Kafka** — распределённый брокер сообщений, ориентированный на потоки событий и
высокую пропускную способность. В отличие от классических очередей (см. тему
`jms`), Kafka хранит сообщения в **логе**: они не удаляются после прочтения, а
лежат заданное время, и разные потребители читают их независимо, отслеживая свою
позицию. Нужен для event-driven архитектур, журналирования событий, интеграции
сервисов и потоковой обработки.

## Ключевые понятия

- **Topic (топик)** — именованный поток записей, куда пишут продюсеры и откуда
  читают консьюмеры.

- **Partition (партиция)** — топик разбит на партиции; внутри партиции порядок
  сообщений строгий. Партиции дают параллелизм и масштабирование.

- **Offset (офсет)** — порядковый номер записи в партиции. Консьюмер хранит свой
  офсет — «до какого места дочитал», поэтому может перечитывать.

- **Producer / Consumer** — отправитель и получатель записей.

- **Consumer group** — группа потребителей с общим `groupId`: партиции топика
  распределяются между её участниками, каждое сообщение обрабатывает один член
  группы. Так Kafka масштабирует чтение.

- **Key (ключ)** — у записи есть ключ; записи с одним ключом попадают в одну
  партицию (гарантия порядка для ключа).

## Spring-абстракции (в коде)

- **KafkaTemplate** — отправка записей (`send(topic, message)`); сериализует
  ключ/значение настроенными сериализаторами.

- **@KafkaListener** — асинхронный метод-потребитель: Spring сам подписывается на
  топик и вызывает метод для каждой записи.

- **NewTopic + TopicBuilder** — декларативное создание топика; `KafkaAdmin`
  заводит его в брокере при старте.

- **auto-offset-reset** — откуда читать новой группе без сохранённого офсета:
  `earliest` (с начала) или `latest` (только новые).

## Чем отличается от JMS

- JMS — **очередь**: сообщение удаляется после доставки одному потребителю.
- Kafka — **лог**: сообщение остаётся, его читают много групп, можно перечитать.
- В Kafka масштабирование чтения — через партиции и consumer groups.

## Запуск

Нужен брокер (в docker-compose.yml, KRaft-режим без ZooKeeper):

```bash
docker compose up -d     # поднять Kafka на localhost:9092
./gradlew test           # round-trip тест (запустится только если брокер доступен)
./gradlew bootRun        # запустить приложение
docker compose down       # остановить брокер
```

Без поднятого брокера интеграционный тест `KafkaRoundTripIT` пропускается
(см. `@EnabledIf`), сборка остаётся зелёной.

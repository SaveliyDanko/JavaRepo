- Stage 03 готов: `docs/parameterized-tests.md` написан — README на него ссылается.

## Под-шаги

### 1. Обновить README ветки под тему
Файл: `README.md` (в ветке `parameterized-tests`, НЕ в `main`).
- Сохранить общую шапку репозитория (назначение, стек), но добавить раздел про
  активную тему ветки — по образцу гайда `docs/how-to-add-a-topic.md` (эталон —
  ветка `jms`).
- Раздел «Тема ветки: @Parameterized Tests (JUnit 5)»: 2–3 предложения о том,
  что показывает пример (один SUT `NumberClassifier`, один тест-класс с
  источниками параметров JUnit 5).
- Обновить блок «Структура» — указать пакет темы:
  ```
  src/main/java/com/savadanko/javarepo/parameterizedtests/NumberClassifier.java
  src/test/java/com/savadanko/javarepo/parameterizedtests/NumberClassifierParameterizedTest.java
  ```
- Ссылка на сводку: «Теория — см. `docs/parameterized-tests.md`». Теорию в
  README НЕ дублировать (правило гайда, шаг 6).
- Команда запуска: `./gradlew test`.
- Что показывает: README — точка входа в тему, теория вынесена в сводку.

### 2. Финальный прогон тестов
- Выполнить `./gradlew test` — все тесты ветки зелёные, детерминированы, без
  сети/ресурсов.
- При падении — это сигнал воркеру вернуться к stage 01/02 (не «чинить» README),
  фиксируется через прогресс реализации, а не здесь.

### 3. Сверка проектного DoD (DoD темы целиком)
Свести и проверить по требованиям (`design/01-requirements.md`):
- SUT `NumberClassifier` + `Category` + `isParsableNumber` на месте (stage 01).
- Продемонстрированы все источники параметров (stage 02).
- Сводка `docs/parameterized-tests.md` на месте и связана с кодом (stage 03).
- README ветки обновлён и ссылается на сводку (этот stage).
- `./gradlew test` зелёный.

## Краевые случаи и риски
- НЕ редактировать README в `main` — правки только в ветке темы (правило
  «main держим чистым», `how-to-add-a-topic.md` шаг 1).
- Не дублировать теорию из сводки в README — только ссылка.
- Имена пакета/классов в README должны совпадать с реальным кодом (сверять
  при написании, после stages 01–02).
- Правок `build.gradle.kts` не требуется (`junit-jupiter-params` транзитивно) —
  не добавлять лишних зависимостей.

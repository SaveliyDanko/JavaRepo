## Под-шаги
Файл: `docs/parameterized-tests.md`. Тон — кратко, по делу, без воды (как
эталон JMS из гайда). Структура по `how-to-add-a-topic.md`:

### 1. Заголовок + «Что это и зачем» (2–4 предложения)
- `@ParameterizedTest` прогоняет один тест-метод на многих наборах входных
  данных; решает дублирование однотипных `@Test`. Источник параметров задаётся
  аннотацией.

### 2. Ключевые понятия (список, по паре предложений)
- `@ParameterizedTest` + атрибут `name` (читаемые имена кейсов).
- `@ValueSource` — массив литералов одного типа (один параметр).
- `@MethodSource` — параметры из `static`-метода-фабрики (`Stream`/`IntStream`/
  `Stream<Arguments>`), когда нужны вычисления или несколько аргументов.
- `@CsvSource` — табличные строки «вход, ожидание»; встроенная конверсия в
  примитивы и `enum`.
- `@EnumSource` — перебор констант enum, с фильтром `names` + `mode`
  (`INCLUDE`/`EXCLUDE`).
- `@NullSource` / `@EmptySource` / `@NullAndEmptySource` — краевые значения для
  ссылочных типов; комбинируются с другими источниками на одном методе.

### 3. Абстракции/инструменты, использованные в коде
- Связать каждый источник с конкретным методом в
  `NumberClassifierParameterizedTest` и с контрактом `NumberClassifier`
  (even/odd/prime, `classify → Category`, `isParsableNumber`).
- Отметить, что отдельная зависимость не нужна: `junit-jupiter` уже включает
  `junit-jupiter-params`.

### 4. «Полезно знать» (опционально)
- Расширения темы вне v1: `@CsvFileSource` (данные из ресурса), кастомные
  `ArgumentsProvider`/`ArgumentConverter`/`ArgumentsAggregator`.
- Несколько источников допустимо вешать на один метод.
- Запуск: `./gradlew test`.

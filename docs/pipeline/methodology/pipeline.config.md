## Гейты пайплайна
Два типа гейтов. **Внутренние гейты роли (GR)** роль проходит сама (через
«Шаг 0») — человек подтверждает результат ВНУТРИ фазы. **Гейты перехода (GT)**
применяет Дирижёр, решая запустить следующую фазу. Колонки — политика по
режиму (пресету).

### Внутренние гейты роли (применяет роль)
| ID  | Гейт | Роль | interactive | mixed | autonomous |
|-----|------|------|-------------|-------|------------|
| GR1 | Резюме требований | 01 | manual | auto   | auto |
| GR2 | Архитектура       | 01 | manual | manual | auto |
| GR3 | Каркас stages     | 02 | manual | auto   | auto |
| GR4 | Батч детализации  | 02 | manual | auto   | auto |
| GR5 | Вердикт ревью     | 04 | manual | manual | auto-with-guard |
| GR6 | Вердикт приёмки   | 05 | manual | manual | auto-with-guard |
| GR7 | Триаж изменения   | 06 | manual | manual | auto |

### Гейты перехода фаз (применяет Дирижёр при входе в фазу)
| ID  | Переход (запуск роли) | Сигнал готовности | interactive | mixed | autonomous |
|-----|------------------------|-------------------|-------------|-------|------------|
| GT1 | → DETAIL (02)     | design подтверждён (GR1/GR2)       | auto   | auto   | auto |
| GT2 | → IMPLEMENT (03)  | флаг «Готовность к разработке» = да | manual | manual | auto-with-guard |
| GT3 | → REVIEW (04)     | stage = ready-for-review           | auto   | auto   | auto |
| GT4 | → ACCEPTANCE (05) | все stages = approved              | manual | manual | auto-with-guard |
| GT5 | → CHANGE (06)     | новый CR                           | auto   | auto   | auto |

GT применяется только при ВХОДЕ в фазу из предыдущей. Возвраты по
`changes-requested` (ревью/приёмка → реализация) — автоматическая
маршрутизация без гейта перехода.

**Частота срабатывания.** Одноразовые: GR1, GR2, GR3, GT1, GT2.
Повторяющиеся (политика применяется на КАЖДОМ срабатывании):
- GR4 — на каждый батч детализации (роль 02, Шаг B);
- GR5 — на каждый раунд ревью stage;
- GR6 — на каждый раунд приёмки;
- GT3 — на вход в ревью каждого stage;
- GT4 — на каждую попытку приёмки (после доработки);
- GT5 / GR7 — на каждый CR.

Политики гейта:
- **manual** — остановиться, дать сводку, ждать подтверждения человека.
- **auto** — пройти, записав ключевые решения/допущения в журнал решений.
- **auto-with-guard** — пройти, ТОЛЬКО если выполнено guard-условие гейта
  (см. ниже); иначе — эскалация и стоп.

**Guard-условия** (что считается «зелёным» — зависит от гейта; «сборка/тесты»
осмысленны только там, где код уже есть):
- **GT2 → IMPLEMENT** (до кода): флаг «Готовность к разработке» = да И все
  stages детализированы (файлы `stages/NN-*.md` существуют). Сборка/тесты тут
  НЕ применимы — кода ещё нет.
- **GT4 → ACCEPTANCE**: все stages = `approved` И проект собирается.
- **GR5 (вердикт ревью)**: тесты stage зелёные и нет открытых `blocking`.
- **GR6 (вердикт приёмки)**: проектный DoD зелёный (сборка, все тесты,
  сквозной сценарий).

## Override гейтов (опционально)
Точечно переопредели политику отдельных гейтов поверх пресета. Пусто — если
оверрайдов нет. Пример:
```
- GR5: manual   # режим автономный, но вердикт ревью подтверждаю сам
- GT4: manual   # хочу лично давать старт финальной приёмке
```

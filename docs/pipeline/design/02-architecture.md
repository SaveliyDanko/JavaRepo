# Архитектура: тема «@Parameterized Tests» (JUnit 5)

Обновлено: 2026-06-18
Основано на: requirements 2026-06-18

## Цель и границы
Минимальный учебный пример: один SUT (`NumberClassifier`) и набор
параметризованных тестов, демонстрирующих ключевые источники параметров JUnit 5.
Граница — показать **механизм источников**, а не покрыть фреймворк; без
runnable-демо и без тематических зависимостей.

## Ключевые архитектурные решения (и почему)
- **SUT — чистый детерминированный класс** `NumberClassifier` (even/odd/prime),
  без состояния и внешних зависимостей → тесты быстрые и воспроизводимые, фокус
  держится на источниках параметров, а не на логике SUT.
- **Единица демонстрации = источник параметров.** Тесты сгруппированы по
  источнику (`@ValueSource`, `@CsvSource`, `@MethodSource`, `@EnumSource`,
  Null/Empty) → читателю наглядно «какой источник для чего нужен».
- **Небольшой enum-категория как часть результата SUT** (классификация числа в
  категорию) → даёт естественный объект для `@EnumSource`, без искусственного
  enum «ради аннотации».
- **Без `application`-плагина и Demo/`main`** (вне объёма v1) → ветка остаётся
  тесто-центричной, как требует тема; запуск только через `./gradlew test`.
- **Отдельная зависимость не нужна:** `org.junit.jupiter:junit-jupiter` уже
  тянет `junit-jupiter-params` → `build.gradle.kts` ветки совпадает с `main`,
  правок зависимостей не требуется.
- **Раскладка и стиль — по аналогии с темой `cron`:** пакет
  `com.savadanko.javarepo.parameterizedtests`, сводка
  `docs/parameterized-tests.md`, README ветки со ссылкой на сводку.

## Компоненты и связи
- **`NumberClassifier`** (`src/main`) — SUT: булевы предикаты (even/odd/prime)
  + классификация числа в enum-категорию. Ни от чего не зависит.
- **Параметризованные тесты** (`src/test`) — фокусные тесты, по одному «срезу»
  на источник параметров; каждый вызывает `NumberClassifier`.
- **`docs/parameterized-tests.md`** — теоретическая сводка (формат
  `how-to-add-a-topic.md`).
- **README ветки** — что внутри + ссылка на сводку.

Поток: тест-данные (аннотация / `@MethodSource`-метод / enum) → параметр(ы)
теста → вызов `NumberClassifier` → assert.

## Стек и почему
Java 21, Gradle (Kotlin DSL), JUnit 5 (Jupiter + Jupiter Params — уже внутри
`junit-jupiter`). Без тематических зависимостей — соответствует чистоте ветки,
ответвлённой от `main`.

## Главные риски и открытые вопросы
- **Расползание объёма:** легко уйти в `@CsvFileSource` / кастомные провайдеры —
  держим их вне v1, упомянем в сводке как «расширения темы».
- **Гранулярность тестов:** «класс на источник» vs «один класс, методы по
  источникам» влияет на читаемость — решает архитектор (роль 02) при
  детализации; зафиксировано в `decisions.md`.
- **Контракт `isPrime` на краях** (0, 1, отрицательные) — определить при
  детализации/реализации, чтобы тест-данные были однозначны.

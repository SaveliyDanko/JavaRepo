# Журнал решений

Решения и допущения, принятые агентом при прохождении auto-гейтов.
Формат строки: дата · этап · решение · причина.

- 2026-06-18 · DESIGN(01) · Архитектура принята авто (гейт GR2 = auto в режиме autonomous) · до кода guard не требуется; артефакт зафиксирован в `design/02-architecture.md`.
- 2026-06-18 · DESIGN(01) · Единица демонстрации = источник параметров; тесты группируются по источнику · максимальная учебная читаемость «какой источник для чего».
- 2026-06-18 · DESIGN(01) · В SUT вводится enum-категория, в которую классифицируется число · даёт естественный объект для `@EnumSource` без искусственного enum.
- 2026-06-18 · DESIGN(01) · `build.gradle.kts` ветки оставляем без изменений · `junit-jupiter` уже включает `junit-jupiter-params`; чистота как в `main`.
- 2026-06-18 · DESIGN(01) · Гранулярность тестов («класс на источник» vs «один класс») отдана архитектору (роль 02) · деталь реализации, не уровень архитектуры.
- 2026-06-18 · DETAIL(02) · Каркас stages принят авто (гейт GR3 = auto) · 4 stages (SUT → тесты → сводка → README/DoD), записаны в `stages/summary-stages.md`.
- 2026-06-18 · DETAIL(02) · Батч детализации 1 принят авто (гейт GR4 = auto) · детализированы stages 01–03; stage 04 — следующим тиком (N=3 по умолчанию).
- 2026-06-18 · DETAIL(02) · Гранулярность тестов = ОДИН тест-класс `NumberClassifierParameterizedTest`, методы по источникам · учебная читаемость «все источники в одном месте» важнее дробления на файлы.
- 2026-06-18 · DETAIL(02) · Контракт `isPrime`: `n < 2` → false (0, 1, отрицательные не простые); проверка делителей до `d*d<=n` через long · снимает открытый вопрос архитектуры о краях, делает тест-данные однозначными.
- 2026-06-18 · DETAIL(02) · `Category{NEGATIVE,ZERO,ONE,PRIME,COMPOSITE}` + метод `isStandard()` · даёт естественный объект для `@EnumSource` и демонстрацию фильтра `names`/`mode`.
- 2026-06-18 · DETAIL(02) · Null/Empty источники демонстрируем на `NumberClassifier.isParsableNumber(String)` · `@NullSource`/`@EmptySource` применимы к ссылочным типам, а не к `int`; нужен строковый метод в SUT.
- 2026-06-18 · DETAIL(02) · Батч детализации 2 принят авто (гейт GR4 = auto) · детализирован stage 04 (README ветки + финальный DoD); недетализированных stages не осталось.
- 2026-06-18 · DETAIL(02) · Флаг «Готовность к разработке» = да (все 4 stages `done`) · handshake воркеру (роль 03): план можно передавать в IMPLEMENT.

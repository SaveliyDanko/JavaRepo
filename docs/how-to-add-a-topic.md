# Как добавлять новую тему

Краткий гайд по формированию учебной темы в этом репозитории. Эталон стиля —
тема JMS (ветка `jms`, код + `docs/jms.md`): кратко и по делу.

## Шаги

1. **Ветка от `main`.** Создай ветку с именем темы (kebab-case):
   `git checkout main && git checkout -b <тема>` (например `jms`, `jpa`, `concurrency`).
   `main` остаётся чистым — тематические зависимости только в ветке.

2. **Зависимости.** Добавь нужные библиотеки в `build.gradle.kts` этой ветки.
   В `main` их не переносим.

3. **Учебный код** в `src/main/java/com/savadanko/javarepo/<тема>/`.
   Небольшие фокусные классы, показывающие суть темы. Сопровождай **короткими
   комментариями** — что и зачем делается (не пересказ синтаксиса).

4. **Тест-проверка** в `src/test/...`. Хотя бы один тест, доказывающий, что
   пример работает (как round-trip тест в JMS). Прогоняй `./gradlew test`.

5. **Теоретическая сводка** `docs/<тема>.md` — см. формат ниже.

6. **README ветки** обнови под тему и сошлись на `docs/<тема>.md` (не дублируй
   теорию в README).

## Формат теоретической сводки (`docs/<тема>.md`)

Цель — закрепить понимание, а не написать учебник. Держись кратко.

- **Заголовок + «Что это и зачем»** — 2–4 предложения: что это и какую проблему
  решает.
- **Ключевые понятия** — список; на каждое понятие буквально пара предложений:
  что это и для чего нужно. Раскрывай понятие целостно только если без этого
  не понять.
- **Абстракции/инструменты, использованные в коде** — кратко, чтобы связать
  теорию с примером.
- **«Полезно знать»** (опционально) — несколько практических заметок (подводные
  камни, расширения темы).

Тон: кратко, по делу, без воды. Если понятие очевидно из названия — не
расписывай.

## Чек-лист перед коммитом

- [ ] Работаю в тематической ветке, не в `main`
- [ ] Код с короткими поясняющими комментариями
- [ ] Тест проходит (`./gradlew test`)
- [ ] Есть `docs/<тема>.md` в нужном формате
- [ ] README ветки ссылается на сводку

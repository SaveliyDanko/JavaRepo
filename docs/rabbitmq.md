# RabbitMQ в Spring (AMQP)

Краткая теоретическая сводка. Код — в `src/main/java/com/savadanko/javarepo/rabbitmq/`.

## Что это и зачем

**RabbitMQ** — брокер сообщений, реализующий протокол **AMQP**. Нужен для
асинхронного, слабосвязанного обмена с **гибкой маршрутизацией**: продюсер не
знает получателей, а exchange по правилам раскладывает сообщения по очередям.
Силён в сложных схемах доставки (фанаут, маршрутизация по ключу/шаблону), в
гарантиях доставки и подтверждениях. В отличие от Kafka (лог событий), Rabbit —
классическая очередь: сообщение доставляется потребителю и удаляется.

## Модель AMQP (ключевое отличие)

В JMS шлют прямо в очередь/топик. В AMQP между продюсером и очередью стоит
**exchange**:

```
producer → exchange ──(binding по routing key)──→ queue → consumer
```

- **Exchange** — точка входа: принимает сообщения и маршрутизирует их. Типы:
  - **direct** — в очереди с точным совпадением routing key (используем здесь);
  - **fanout** — во все привязанные очереди (broadcast);
  - **topic** — по шаблону ключа с `*` и `#`;
  - **headers** — по заголовкам сообщения.
- **Queue (очередь)** — буфер, где копятся сообщения до получения.
- **Binding** — правило связи exchange → queue (для direct/topic — с routing key).
- **Routing key** — «адрес» сообщения; exchange сопоставляет его с binding-ами.

## Ключевые понятия

- **RabbitTemplate** — отправка: `convertAndSend(exchange, routingKey, msg)`.
- **@RabbitListener** — подписка на **очередь** (не на exchange), вызывается для
  каждого сообщения.
- **Queue / DirectExchange / Binding (бины)** — объявляют топологию; RabbitAdmin
  создаёт их в брокере при старте.
- **durable** — у очереди/exchange флаг: пережить рестарт брокера.
- **ack (подтверждение)** — потребитель подтверждает обработку; без ack
  сообщение вернётся в очередь (надёжная доставка). Есть авто- и ручной режим.

## Сравнение брокеров (темы)

- **JMS** — очередь/топик, шлём прямо в destination.
- **RabbitMQ** — очередь + exchange-маршрутизация (этот гибкий слой — его фишка).
- **Kafka** — лог событий: сообщения не удаляются, читаются группами по офсету.

## Запуск

Нужен брокер (docker-compose.yml, образ с management UI):

```bash
docker compose up -d     # RabbitMQ на :5672, UI на http://localhost:15672 (guest/guest)
./gradlew test           # round-trip тест (запустится только если брокер доступен)
./gradlew bootRun        # запустить приложение
docker compose down       # остановить брокер
```

Без поднятого брокера интеграционный тест `RabbitRoundTripIT` пропускается
(см. `@EnabledIf`), сборка остаётся зелёной.
